1. Class Diagram Explanation

Show the full UML diagram, then zoom into the relevant classes.

Our UML Class Diagram shows the classes, attributes, methods, and relationships implemented in BookBase.

Each class box has three sections. The first contains the class name, the second contains its attributes, and the third contains its methods. The plus symbol represents public members, while the minus symbol represents private members. In our JavaScript code, private members use the hash symbol.

The hollow triangle arrow represents inheritance and points toward the parent class. A solid association shows that an object holds a reference to another object, while a dashed arrow shows a dependency.

For account access, Student and Librarian inherit from LibraryUser. LibraryUser stores account information, while its subclasses provide their respective dashboard destinations.

For the student dashboard, Book and StudentProfile inherit from LibraryRecord. Their service classes handle the catalogue, student information, and borrowing requests.

For the administrator dashboard, AdminBook and AdminProfile inherit from AdminRecord. The administrator services handle catalogue management, borrowing transactions, profile updates, and filtering.

These classes have meaningful relationships. For example, LoginController uses LoginService for authentication. AdminCatalogueService creates, updates, and removes books from the catalogue. AdminBorrowingService uses the inventory methods of AdminBook when issuing and returning books.

The classes share application data through Firebase. Their implementations are organized into separate JavaScript modules to make the OOP structure easier to locate. The source file is shown beneath each class name in our diagram.

2. Four Pillars of OOP

Open the corresponding files in VS Code while explaining each example.

BookBase applies the Four Pillars of Object-Oriented Programming: encapsulation, inheritance, polymorphism, and abstraction.

Encapsulation

Show private fields in oop/encapsulation.js, then AdminBook.#copies in oop/inheritance.js.

First is encapsulation. Encapsulation controls access to an object's internal state. Our classes use private fields and public methods.

For example, AdminBook stores its inventory in the private field #copies. Other parts of the application cannot directly modify this field. Instead, they use issueCopy(), addCopies(), and returnCopy(), which validate the operation before changing the inventory.

Private fields and methods are also used to manage account information, service dependencies, and login form state.

Inheritance

Show extends and super() in oop/inheritance.js.

Second is inheritance. Inheritance allows child classes to reuse the behavior of their parent class.

Student and Librarian extend LibraryUser. They inherit its public identity methods, and their constructors call super() to initialize the parent's fields.

Similarly, Book and StudentProfile extend LibraryRecord, while AdminBook and AdminProfile extend AdminRecord.

Polymorphism

Show oop/polymorphism.js, then the overridden methods in oop/inheritance.js.

Third is polymorphism. Polymorphism allows the same method call to produce behavior appropriate to the actual object.

Our dashboardPath(account) function calls account.getDashboardPath(). If the object is a Student, it returns the student dashboard path. If it is a Librarian, it returns the administrator dashboard path.

Our recordSummary(record) function also calls getSummary() on different book and profile objects. Each subclass provides its own implementation.

Abstraction

Show the base-class checks in oop/encapsulation.js and service methods in oop/abstraction.js.

Fourth is abstraction. Abstraction exposes the operations needed by other parts of the system while keeping implementation details inside the classes.

Our base classes define methods that their subclasses must implement. Because JavaScript does not have a native abstract keyword, we enforce these contracts through runtime checks.

Our service classes also hide detailed Firebase operations. For example, the interface calls requestBook(), approve(), or removeBook(), while the service handles the validation and database transaction.

The pillars can overlap within one class. Separating the files helps us present the code, but the actual use of private fields, inheritance, overridden methods, and service operations demonstrates the OOP implementation.
